# 按 tasks.md 开发

输入：`$ARGUMENTS`
- 第一个参数：需求文件夹（如 `specs/01-user-login`）。缺失时列出 `specs/` 下各文件夹及其完成进度，让用户选择。
- 第二个参数：任务编号（可选）。

## 步骤

1. **读取上下文**：完整阅读该文件夹下的 `requirements.md`、`design.md`、`tasks.md`，以及 `specs/00-overview/README.md`（如存在）。
2. **选定任务**：指定了编号就做该任务；否则选第一个 `- [ ]` 的任务。若它依赖的前置任务未完成，先提醒用户。
3. **开发**：按 design.md 实现，遵循项目现有代码风格。一次只做一个任务（含其子任务），不要顺手做后面的任务。
4. **验证**：运行相关测试/构建/lint。验证失败就修复，修不好则不要标记完成，向用户说明原因。
5. **更新 tasks.md**：验证通过后，把该任务的 `- [ ]` 改为 `- [✅]`。
   - 子任务逐个标记；父任务在所有子任务都完成后才标记 `[✅]`。
   - 只改复选框，不改动任务文字。
   - 如果实现时偏离了 design.md，同步更新 design.md 并告诉用户。
6. **汇报**：说明做了什么、改了哪些文件、验证结果、当前进度（如 `3/8 已完成`），以及下一个任务是什么。然后停下等待用户指示——除非用户说“全部做完”，那就继续循环执行直到所有任务都是 `[✅]`。
